### 要点

- 流式支付用持续的资金流取代一次性的大额交易，让费用在服务使用期间以很小的增量快速累积或结算。
- AI 智能体通过流式支付，实时为难以预测、不断变化的工作负载付费，消除预付额度占用资金的问题，以及按月出账可能带来的支出失控风险。
- 在机器对机器商业活动中，匿名软件没有法律身份或信用评分。流式支付让数据交付与价值交付同步，将对手方风险限制在一个极小的单位内，从而解决这一问题。
- 为了经济地处理高频小额支付，可以采用支付通道等链下方案，快速完成金额低于一美分的小额支付。

AI 智能体在开始任务之前，往往不知道任务究竟要花多少钱。

它可能要查询多个数据提供商，才能找到所需的信息；可能调用模型十次，也可能调用一万次；一个计算任务可能三十秒就结束，也可能运行数小时。

服务是一点点使用的，但支付通常不是。

大多数数字服务通过预先收费、出售预付额度，或统计用量后统一出账来解决这个问题。这些模式行之有效，却让价值被消耗的时间与资金实际转移的时间产生了间隔。

流式支付缩小了这一间隔。

付款不必在任务开始前一次支付固定金额，也不必等到结束后统一结算，而是可以随着使用量增加，以更小的增量累积或转移。服务可以按每秒算力、每次 API 请求、每个生成的 token，或其他可计量单位收费。

这对 AI 智能体和其他自主软件尤其有用，因为它们的工作负载往往既多变，又由程序驱动。智能体可以使用资源、按实际用量付费，并在任务完成或达到支出上限时停止。

流式支付也能减少双方承担的资金风险。

预付费时，买方可能需要先投入比任务最终所需更多的资金；后付费时，提供方则要先交付服务，之后才能收款。如果支付紧跟着使用过程，双方尚未结清的金额都可以小得多。

底层机制可以有所不同。有些系统随时间持续累积链上余额；另一些系统则计量活动，并频繁进行链下小额支付。无论哪种方式，目标都一样：让支付比传统的一次性结算更紧密地跟随使用量。

本文介绍流式支付的工作原理、不同实现方式，以及它为何开始与 AI 智能体、机器对机器商业活动和其他按用量计费的数字消费产生关联。

## 什么是流式支付？

流式支付（streaming payments）是指随着服务被使用，以小额增量累积或结算的支付，而不是在事前或事后进行一次大额支付。

支付可以按时间计量，例如每秒算力的费用；也可以按其他使用单位计量，例如 API 请求次数、生成的 token 数量、传输字节数或消耗的千瓦时。

关键在于，让使用量与支付更加同步。

这并不一定意味着资金真的每秒转移一次。系统可以持续计量用量，同时更新链下余额、在智能合约中累积应付金额，或在之后将多个小额增量合并结算。

有几个相关术语需要区分：

- **小额支付（micropayment）：** 金额很小的支付，往往小到通过传统支付网络处理并不划算。
- **按用量支付（metered payment）：** 与可计量的消耗单位挂钩的支付，例如一次 API 调用、一 GPU 秒或一兆字节数据。
- **按秒支付（per-second payment）：** 按用量支付的一种具体形式，费用取决于经过的时间。
- **按用量定价（usage-based pricing）：** 确定每个单位价格的定价模式，例如每 1,000 个 token 收费 0.01 美元。

流式支付可以结合上述所有思路，但这些概念并不等同。

例如，云 GPU 服务可以按秒收费。其定价依据是使用量，计量单位是消耗的计算时间，而支付流决定应付金额以多高的频率累积或转移。

## 流式支付的类型

流式支付有不同的实现方式，但最有用的区分标准是：支付状态多久更新一次，以及该状态在哪里维护。

### 链上累积

有些系统不会每秒转移资金，而是由智能合约记录支付流的规则，计算随时间累积的金额。

例如，付款方可以将代币存入合约，并设定收款方每小时获得 1 美元。区块链不会每小时处理 3,600 笔独立支付。合约会记录开始时间和费率，在收款方提取资金或支付流更新时，计算应付金额。

[**Sablier**](https://docs.sablier.com/concepts/lockup/overview) 和 [**Superfluid**](https://docs.superfluid.org/docs/concepts/superfluid#money-streaming) 等协议在以太坊上采用了这一模式的不同变体。

当支付速率预先已知，且随时间的变化可以预测时，这种方式很适用。

典型用例包括：

- **薪资发放：** 报酬持续累积，而不是每月支付一次。
- **代币归属：** 资产按照预定计划逐步解锁。
- **定期资助或津贴：** 资金在固定期间内持续变得可用。

### 链下增量支付

另一些应用无法预先知道最终金额，因为使用量并不规律。

AI 智能体可能在一分钟内发出 12 次 API 请求，下一分钟却一次也没有；模型可能生成 500 个 token，也可能生成 50,000 个；计算任务可能几乎立即完成，也可能运行数小时。

在这些情况下，支付可以跟随实际发生的事件，而不是固定的时钟。

[**支付通道（payment channels）**](https://www.nervos.org/knowledge-base/what_are_payment_channels)很适合这种模式。参与者在链上为通道注资一次，之后就能随着使用过程，反复在链下更新余额。因此，每次小额支付都不需要新增一笔区块链交易。

支付可以在每次 API 请求后、每使用几秒算力后，或每消耗另一个约定的单位后更新。

这种方式尤其适用于：

- **AI 和 API 服务：** 随着请求、推理、token 或算力被使用，逐步付费。
- **带宽和数据服务：** 根据传输字节数或连接时长付费。
- **机器对机器商业活动：** 设备或软件服务频繁进行小额支付，交换能源、存储空间或网络容量等资源。

两种模式的区别很直接：

链上流式支付通常持续计算应付金额；链下流式支付则可以在使用发生时，反复实际更新支付状态。

## 自主支付流的生命周期

无论由哪种架构处理结算，是链上累积还是链下通道，自主支付流都会经历几个不同阶段：

1. **条款**：提供方公布价格、接受的资产、用量单位和服务条件。例如，每处理一个大语言模型 token 收费 0.001 美元，以 USDC 支付。
2. **握手**：服务交付前，付款方的智能体先与提供方建立联系。使用 x402 或 L402 协议等支付层标准时，这一过程可以直接通过 HTTP 完成：客户端请求资源，服务器返回 HTTP 402 Payment Required（需要付款）状态，并随响应附上支付发票和权限受限的身份验证令牌。
3. **授权**：智能体完全自主运行，根据预先配置的预算和速率限制评估发票。随后支付初始发票，获得密码学支付证明，并将证明与令牌一同附上，以授权本次会话。
4. **交付与计量**：提供方验证证明、授予访问权限，并开始记录用量，例如已返回的 API 响应数量或已消耗的计算秒数。
5. **支付更新**：随着智能体使用服务、消耗价值，支付流持续支付相应费用。每个动作都会从智能体的储备资金中触发一笔按比例计算的小额付款。取决于采用链下还是链上架构，这些近乎即时的更新会发生在支付通道内，或智能合约的状态中。
6. **结束**：任务完成、达到预算上限或资金耗尽时，会话结束。双方核对最终用量和支付状态，并结算或关闭相应的支付流或通道。

## 为什么流式支付适合机器对机器商业活动

[机器对机器商业活动](https://www.nervos.org/knowledge-base/what_are_machine_to_machine_payments)（machine-to-machine commerce）往往涉及不断变化的工作负载，最终成本无法预知。AI 智能体可能需要调用 API 十次，也可能需要一万次；可能只需要几秒算力，也可能需要数小时。

传统计费通常让其中一方承担风险。预付费时，买方还不知道会用多少，就要先投入资金；后付费时，提供方先交付服务，之后才能收款。

流式支付让付款以小额增量跟随消费，从而缩小这一间隔。买方只在使用资源时付费，提供方也无须为整个会话提供信用额度。

结合可编程支出上限，流式支付尤其适合高频、按用量计费的服务，这些服务的成本要在任务进行过程中才能逐渐确定。

## 基础设施实例：Fiber Network

[支付通道网络](https://www.nervos.org/knowledge-base/ultimate_guide_to_payment_channels)是实现高频小额支付的一种方式：参与者可以在链下交换余额更新，使用区块链为通道注资，并在必要时结算最终状态。

[Fiber Network](https://www.nervos.org/knowledge-base/what_is_fiber) 是建立在 [Nervos](https://www.nervos.org/) CKB 上的开放点对点支付与兑换网络。它通过支付通道支持[多跳支付](https://www.fiber.world/docs/concept/routing/multi-hop)：只要存在流动性充足的路径，用户就能通过中间节点向收款方付款，无须与对方直接建立通道。

对于流式支付，这意味着 AI 智能体可以在网络中保留流动性，并随着使用过程反复向不同服务付款。每次支付都能避免单独发起基础层交易，而路由（routing）节点可以通过提供流动性和连接收取少量转发费用。

Fiber 还支持多种资产类型，包括 CKB 和稳定币等用户自定义代币（User-Defined Tokens），让流式支付可以使用更适合为数字服务定价的资产。

要进一步了解 Fiber 如何为这种自主经济提供基础设施，请参阅[*《Fiber Network：面向数字经济的开放支付网络》*](https://www.nervos.org/knowledge-base/fiber_network#machine-to-machine_payments)*。*

## 结语

传统金融支付网络围绕由人发起的单次交易而设计。在由自主 AI 智能体和互联机器驱动的经济中，价值必须像被消耗的计算资源一样顺畅流动。流式支付结合实时计量、链下支付通道和可编程结算层，让支付时间与测得的服务用量保持一致。虽然没有一种实现适合所有场景，但可靠的计量和范围明确的授权，为将持续支付带入机器经济提供了必要基础。

## 常见问题

### 面向 AI 的流式支付是什么？

流式支付让 AI 智能体在使用 API 调用、算力、数据或模型推理等可计量资源时逐步付费，而不是一次预付全部费用，或事后收到一张总账单。

### AI 智能体能自主付款吗？

可以。AI 智能体可以在运营者设定的规则内付款，例如支出上限、获准的提供方、允许使用的服务和有效期。

### AI 智能体使用流式支付有哪些风险？

主要风险包括支出失控、密钥管理薄弱、权限过宽和用量争议。可以通过预算、速率限制、允许名单、监控和可撤销授权来降低这些风险。

### 流式支付必须使用加密货币吗？

不必。中心化系统也能支持流式支付或按用量计费，但加密货币和稳定币具有可编程、全球可转移和全天候可用的特点，因此很有用。

### 流式支付在链上还是链下进行？

两者都可以。链上系统通过智能合约累积或结算金额；支付通道等链下系统则更新余额，无须把每笔小额支付都记录在区块链上。

### 为什么支付通道适合流式支付？

支付通道支持频繁的小额支付，无须为每笔支付新建区块链交易，因此尤其适合高频、按用量的支付。

### 流式支付可能如何改变企业 AI 计费？

它可以让企业随着 AI 资源的使用逐步付费，而不必只依赖预付额度或月度账单。这有助于改进成本跟踪，并实时执行支出上限。
