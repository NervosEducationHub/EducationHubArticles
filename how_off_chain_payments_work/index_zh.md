## 要点

* **链下支付将支付活动移出区块链基础层**，减少逐笔在链上记录交易的需要。  
* **不同链下方案有不同取舍。** 托管支付、侧链、Rollup 和支付通道，在扩容方式和安全来源上有很大差异。  
* **支付通道让参与者在链上锁定一次资金后，反复在链下交易**，主要在开启、关闭和强制执行通道约定时使用区块链。  
* **支付通道网络将各个通道连接起来**，让没有直接连接的用户也能通过路由完成支付。  
* **Fiber Network 将支付通道模型应用于 CKB**，支持高频多资产支付、支付中的资产兑换，以及与比特币闪电网络的互操作。

区块链是出色的结算系统，能让互不信任的参与者对资产归属达成一致，而无需依赖中心化中介。

但这种安全性是有成本的。

每笔链上支付都必须进入区块链的全局共识过程，竞争有限的区块空间，最终成为一份在全网复制的账本的一部分。当可靠的结算保证比速度或成本更重要时，这种模型很有效；当支付金额很小、频繁发生或持续进行时，它的效率就低得多。

试想，每次 API 请求、电动汽车充电的每一秒，或每笔不足一美分的机器支付，都在公有区块链上单独记录为一笔交易。即使是相对较快的区块链，最终也会遇到同一个基本问题：一项可能只涉及两方的活动，却要求整个网络处理每次支付，成本太高。

链下支付将这些活动移出了全局共识流程。

参与者不再把每笔支付单独提交到基础区块链，而是通过另一套系统交易，只在确实需要区块链安全保障的地方使用它，例如结算、强制执行约定、解决争议，或将资金转入、转出系统。

需要分清的是，“链下”（off-chain）是一个总称，并非单一架构。交易所在私有数据库中更新余额，是链下活动；Rollup 在以太坊之外执行交易，也是；通过支付通道网络传递的闪电支付，同样是。

它们以截然不同的方式提高可扩展性，也依赖截然不同的信任假设。

本文将介绍这些方案如何工作、安全性来自哪里，以及支付通道网络为何特别适合高频、小额、实时的支付。



## 什么是链下支付？

链下支付是不必将每笔交易都直接记录在区块链基础层上的支付。

进行链上支付时，交易会广播到网络，被纳入区块，并通过区块链的共识过程验证。链下支付则把其中部分或全部活动放在别处进行。

这个“别处”有多种形式。中心化交易所可以在私有数据库中更新余额；Rollup 可以在基础链之外执行交易，之后再把数据或证明提交回去；支付通道（payment channels）则允许两名参与者私下交换已签名的余额更新，只在开启、关闭通道或出现争议时使用区块链。

这些系统的共同点，是减少基础区块链必须直接处理的活动量。

它们*不相同*的地方，是保障资金安全的方式。

一些链下系统要求用户信任中介，另一些则保持非托管性质，依靠密码学和区块链强制执行的规则。有些系统定期向基础链提交交易数据，另一些则可能让每笔支付完全留在链下。

所以，“链下”实际描述的是交易在哪里处理，而非背后的安全模型。



## 链上支付 vs 链下支付

基本取舍很直观：链上支付的每笔交易都使用区块链共识过程，而链下系统不必让每笔支付都经过这一过程。

| 因素 | 链上支付 | 链下支付 |
| ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 支付活动发生在哪里 | 直接发生在区块链基础层。 | 发生在基础层之外，通过次级协议或中心化系统进行。 |
| 区块链如何参与 | 每笔交易都必须提交给区块链，由其处理。 | 取决于设计。区块链可用于存入和提取资金、定期结算、开启和关闭通道，或解决争议。 |
| 速度 | 受出块、确认要求和网络拥堵限制。 | 通常快得多，因为单笔支付无需等待基础层确认。 |
| 成本 | 每笔交易通常都产生区块链网络费用。 | 通常降低每笔支付的区块链成本，但仍可能产生路由费、服务费、证明成本或其他费用。 |
| 可扩展性 | 受基础区块链吞吐量和区块空间限制。 | 将反复发生的活动移出基础层，可支持大得多的交易量。 |
| 安全与信任 | 直接由区块链共识规则保障。 | 因架构而异，可能依赖托管方、另一组验证者、密码学证明，或由区块链强制执行的合约。 |
| 链上记录 | 每笔支付都成为区块链交易历史的一部分。 | 单笔支付可能永不上链，也可能通过聚合数据、证明或最终结算交易间接体现。 |



## 链下支付的主要方案

有几种根本不同的方式，可以将支付移出区块链基础层。

比较它们时，最有用的问题不只是速度多快、成本多低，而是基础链不再直接处理每笔交易之后，支付靠什么值得信赖。

有些系统让你信任一家公司，有些让你信任另一条区块链。Rollup 依靠基础链验证或挑战交易批次，支付通道则依靠合约，使参与者在必要时能在链上强制结算最新的有效余额。

这些差异形成了四种主要方案。

### **1. 托管式链下支付**

最简单的链下支付，是托管平台内部的转账。

[Binance Pay](https://pay.binance.com/en) 是一个典型例子。币安用户可以使用二维码、支付链接、电子邮箱地址、电话号码或币安 ID，向其他用户发送加密货币。收款人的币安账户几乎立即到账，而且大多数点对点转账不收手续费。

但如果 Alice 通过 Binance Pay 向 Bob 发送价值 100 美元的 USDT，币安并不需要向区块链广播一笔 USDT 交易。

Alice 和 Bob 的资金都已经由币安保管，因此平台可以内部处理支付：Alice 的账户余额减少 100 美元，Bob 的增加 100 美元。币安仍是底层资产的托管方，变化的只是内部记录，即每位用户拥有多少资产。

这与 Alice 从自己的钱包向 Bob 的钱包发送 USDT 根本不同。后一种情况必须把转账提交给相应区块链，并由网络确认。

**优势：** 这一模型效率极高。同一平台用户之间的支付可以近乎即时完成，并完全免去区块链网络费。用户也无需考虑区块确认、gas 费、路由或流动性管理。

**取舍：** 效率来自以对托管方的信任，取代区块链的强制执行。币安控制资产，维护用户余额的权威记录。因此，用户必须信任它能够保持偿付能力、保障资金安全、维护准确记录，并兑现提款。

换言之，托管支付通过把交易和资金控制权一并移到链下，实现了极佳的速度和可扩展性。

### **2. 侧链**

侧链（sidechain）为用户提供另一条可以交易的区块链，从而将活动移出基础链。

侧链拥有自己的区块、共识规则，以及验证者或矿工集合。资产可以通过跨链桥在基础链和侧链之间转移，之后的交易按侧链规则进行。

*需要注意，这些交易并非字面意义上的“链下交易”，而是另一条区块链上的链上交易。被移出基础层的是工作负载。*

**优势：** 侧链可以设计得吞吐量更高、费用更低、出块更快，或提供基础链不支持的功能。开发者在更改执行环境和网络规则方面，也拥有很大的自由。

**取舍：** 侧链不会自动继承所连接区块链的安全性。用户必须信任侧链自己的共识系统，以及在两个网络之间移动资产所用的机制或跨链桥。

因此，更合适的理解是：侧链是用来承载更多活动、与基础链并行运行的区块链，而非安全性直接来自基础链的延伸。

### **3. Rollups**

Rollup 采取另一种方式。它不要求基础链逐笔执行交易，而是在独立环境中执行，将多笔交易合为批次，再由基础链验证和结算产生的状态。

主要有两种设计。

**乐观 Rollup（Optimistic Rollup）** 默认提议的状态更新有效，除非有人在争议期内成功提出挑战。

**ZK Rollup** 生成密码学有效性证明，表明新状态确实由先前状态正确推导而来。

两者的大部分计算都在 Layer 1 之外进行，而基础链仍负责强制执行 Rollup 的状态承诺和安全规则。

**优势：** Rollup 可以显著提高吞吐量，同时与基础链安全性保持比侧链强得多的联系。它还支持众多用户与共享状态交互的通用应用，包括去中心化交易所、借贷市场、游戏和其他去中心化应用。

**取舍：** Rollup 仍会消耗基础层资源。批次、状态承诺、证明和／或交易数据，最终仍须提交到 Layer 1。因此，使用基础链的成本是被降低，并分摊到多笔交易上，而非完全消除。

它们还引入了额外基础设施和复杂性。ZK Rollup 需要生成和验证证明，Optimistic Rollup 则通常要求经过挑战期，向基础链的原生提款才能被视为最终确定。

因此，如果目标是扩展可编程区块链环境，而非专门为支付优化，Rollup 尤其有用。

### **4. 支付通道**

支付通道采用一种更专门的方式。

两名参与者不再反复向区块链提交交易，或定期批量提交，而是把资金锁入链上合约，之后通过交换共享余额的已签名更新，直接彼此交易。

假设 Alice 和 Bob 开启一个存有 100 美元的通道。Alice 向 Bob 支付 1 美元时，无需广播区块链交易，只需创建一个新的有效通道状态，表示 Alice 现在拥有 99 美元，Bob 拥有 1 美元。

Alice 再次向 Bob 支付时，就用另一个状态替换它。

他们可以反复这样做，无需要求区块链处理每笔支付。最终关闭通道时，可以把最新的有效余额结算到链上。

因此，区块链从每笔支付的处理者，变成了约定的强制执行者。

**优势：** 通道完成注资后，单笔支付不再需要区块空间或基础层确认。支付可以在极低延迟下完成，基础层费用可分摊到大量交易中，单次通道更新也无需向全网公布。参与者仍然掌控资金：如果合作中断，通道协议提供了一条路径，通过底层区块链强制落实有效状态。

**取舍：** 支付通道用通道流动性（channel liquidity）限制换掉了区块链吞吐量限制。资金必须预先锁入通道，而且流动性具有方向性。这意味着，一个通道即使有 1,000 美元，如果 Alice 一侧目前只有 100 美元，她最多也只能向 Bob 发送 100 美元。剩下的 900 美元在 Bob 一侧，只能用于反方向支付。因此，通道的总容量（channel capacity）即使很充足，仍可能无法路由某笔支付。

直接通道也只连接通道双方。要让这一模型超越两两配对，就需要**支付通道网络**，通过多个相连的通道路由支付（routing）。这又会带来寻路（pathfinding）、流动性管理、可靠性和路由费等方面的挑战。

与 Rollup 不同，支付通道的目标不是重建一个通用的共享执行环境，而是为反复、高效地转移价值提供专用基础设施。



## 四种方案的对比

| 方案 | 什么取代了基础层的直接处理？ | 最适合的场景 | 主要取舍 |
| ---------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **托管支付** | 公司的内部账本 | 平台内转账 | 用户必须信任托管方保管资金 |
| **侧链** | 另一条区块链及其共识系统 | 需要不同规则或更高吞吐量的应用 | 独立的安全假设和跨链桥风险 |
| **Rollup** | 在 L1 之外执行，状态锚定在基础链并由其验证 | 通用应用和共享状态 | L1 数据成本、额外复杂性，以及某些设计中的提款延迟 |
| **支付通道** | 由可强制执行的链上合约支持的已签名状态更新 | 高频、小额、对延迟敏感的支付 | 锁定流动性、路由和通道管理 |

这些方案没有哪一种在所有情况下都“最好”。它们针对的是不同问题。

对于众多用户与共享状态交互的通用应用，Rollup 往往很合适。如果用户愿意信任某个平台，托管账本则格外简单。

但如果要解决的是在保留自主保管能力的同时，频繁、低成本、极低延迟地转移价值，支付通道的架构就特别有用。



## 为什么需要支付通道网络？

同样的双方反复交易时，[支付通道](https://www.nervos.org/knowledge-base/what_are_payment_channels)非常高效。但如果你要与所有可能的收款人分别开启通道，就会在很大程度上失去使用通道的意义。

[**支付通道网络（payment channel networks）**](https://www.nervos.org/knowledge-base/ultimate_guide_to_payment_channels)**将各个通道连接成更大的路由网络，从而解决这一问题。**

如果 Alice 与 Bob 有通道，Bob 又与 Carol 有通道，Alice 就可以通过 Bob 向 Carol 支付，无需再与 Carol 开启新通道。将这一方式扩展到数千个相连通道，只要存在流动性充足的路径，用户就能跨网络支付。闪电网络和 Fiber 都采用这种多跳模型。

专门针对支付，而非通用计算，这一架构有几项重要优势。

### 低延迟支付

链上支付必须等待区块链收录并确认交易，通道支付则不需要。

参与者交换带有密码学签名的通道状态更新。多跳支付中，这些更新沿选定路径上的通道传播。单笔支付完成，无需产生新区块。

区块链仍在后台充当强制执行层：参与者发生分歧，或需要关闭通道时，最终可以在链上强制落实有效通道状态。

这个区别很重要。支付可以在链下于数秒甚至更短时间内完成，即使通道本身可能在很久以后才结算回区块链。

### 高频场景下的低成本

支付通道也改变了重复支付的成本结构。

开启通道需要一笔链上交易，最终关闭时可能还需要一笔。但通道开启期间可能发生的数千笔甚至数百万笔支付，不必各自对应一笔基础层交易。

通道复用越多，最初的区块链成本就能分摊到越多支付上。

这并不意味着通道支付一定免费。通道双方之间的直接支付可能没有路由费，而通过其他节点路由的支付，通常要为转发和流动性向这些节点付费。闪电网络和 Fiber 都允许中间节点收取路由费。

关键区别在于，区块链不会对每笔支付单独收取网络费。对于频繁的小额转账，反复购买区块空间并不划算，支付通道因此格外有吸引力。

### 无需支付中介的自主保管

支付通道网络可以提供链下系统的速度，同时无需用户将资金的保管权交给中心化运营方。

锁入通道的资金，按底层区块链强制执行的规则控制。在通道存续期间，参与者交换已签名的状态，描述资金如何分配。如果一方不再合作，另一方无需获得它或网络运营方的许可，就可以关闭通道，在链上强制结算有效余额。

这与 Binance Pay 一类服务有根本区别。

两种系统都避免把每笔支付写上区块链。但在 Binance Pay 中，币安维护权威账本，控制底层资产；非托管支付通道的参与者，则仍拥有通过基础链强制落实自身资金权益的密码学能力。

这仍有运维责任：如果对手方试图用旧状态结算，通道参与者必须能够自行响应，或通过瞭望塔（watchtowers）等机制响应。但他们不需要把资金托付给支付公司。

### 更好的支付隐私

支付通道也减少了暴露在公有区块链上的金融活动。

如果 Alice 和 Bob 通过同一通道完成 10,000 笔支付，这些单次余额更新不必表现为 10,000 笔公开的区块链交易。区块链主要看到的是建立通道和最终结算通道的交易。

支付通道网络还可以通过洋葱路由（onion routing）增加一层隐私。在闪电网络和 Fiber 中，路由指令经过分层加密，因此中间节点通常只知道支付上一跳来自哪里、下一跳该发往哪里，而不知道完整路径。

这不能与完全匿名混为一谈。单个路由节点仍能了解所转发支付的一些信息，人们还可能根据网络拓扑、时间特征、端点或相互串通的参与者推断更多信息。

更根本的优势是：单笔支付不会向全网广播，也不会被永久记录下来供所有人查看。

这些特性结合起来，使支付通道网络特别适合频繁、小额或对延迟敏感的支付。它们将日常支付活动移出全局共识，同时保留区块链最擅长的用途：强制落实所有权，以及解决争议。

*若想进一步了解这些网络的运作机制，请阅读[《支付通道与支付通道网络终极指南》](https://www.nervos.org/knowledge-base/ultimate_guide_to_payment_channels)*。



## 支付通道网络的实践：闪电网络与 Fiber

支付通道网络的基本思路很简单：在链上锁定价值，将支付移到链下，通过相互连接的通道网络进行路由。

但支付通道网络具备哪些能力，也取决于底层区块链。

闪电网络和 Fiber Network 是一个很有参考价值的对比。两者采用相同的大体架构，包括支付通道、多跳路由和受密码学保护的条件支付，但建立在能力差异很大的基础层上。

### 闪电网络

闪电网络是建立在比特币上的支付通道网络。

两名参与者可以将比特币锁入一个共同控制的链上注资输出，再在链下更新这些资金的分配。如果用户之间没有直接通道，闪电网络会通过其他参与者的通道路由支付。

多跳支付通过[哈希时间锁合约（Hashed Timelock Contracts，HTLC）](https://docs.lightning.engineering/the-lightning-network/multihop-payments/hash-time-lock-contract-htlc)保障。简化来说，每一跳都只在截止时间之前揭示同一个密码学秘密值的条件下，同意转发支付。这样，各次转移被关联起来，中介不能只收取入账支付，却不完成对应的出账支付。

闪电网络已经证明，去中心化支付通道网络可以转移比特币，而不必为每笔支付创建链上交易。但运行这样的网络，也带来了简单区块链转账所没有的挑战。

最重要的是流动性管理。

通道流动性具有方向性。如果 Alice 和 Bob 共享一个存有 1 BTC 的通道，但全部余额目前都在 Alice 一侧，Alice 最多可以向 Bob 发送 1 BTC；在部分余额转移到 Bob 一侧之前，Bob 却无法向 Alice 回付任何资金。

同样的限制也适用于整个网络。支付要成功，选定路径上的每个通道都必须在正确方向上具备足够流动性。

这一点对收款尤为重要。如果新闪电网络用户自行开启并全额注资一个通道，起初通过该通道拥有的是出站流动性（outbound liquidity），没有入站流动性（inbound liquidity）。在该用户能够收款前，还需要其他参与者向通道对手方一侧投入或转移比特币。Lightning Labs [指出](https://lightning.engineering/lightning-pool-whitepaper.pdf)，获取并维持入站流动性，是商户和路由节点的重要运营要求。

为应对这些限制，闪电网络已发展出一套工具生态，包括通道再平衡、潜水艇交换（submarine swaps）和流动性市场。但流动性仍需参与者主动管理。

还有一个更广泛的架构限制：比特币自身只原生记录一种资产，即 BTC，而且刻意提供了相对受限的脚本环境。

这并不意味着闪电网络永远无法支持其他资产。Taproot Assets 等协议可以把发行资产带入兼容闪电网络的通道，并通过网络路由。但这些能力是通过额外协议层添加的，并非比特币本身的原生属性。

### Fiber Network

[Fiber Network](https://www.fiber.world/) 将支付通道模型应用于 CKB。CKB 是一条基于 UTXO 的可编程区块链，拥有 RISC-V 虚拟机 [CKB-VM](https://docs.nervos.org/docs/ckb-fundamentals/ckb-vm)。

基本机制并不陌生：参与者将资产锁入通道，在链下交换已签名的状态更新；没有直接通道时，则通过中间节点路由支付。关闭通道或发生争议时，CKB 充当结算和强制执行层。

区别在于，CKB 的可编程性让 Fiber 能将支付通道模型扩展到不仅以基础资产计价的支付。

#### **多资产支付**

Fiber 的设计支持以不同资产计价的通道，包括 CKB 和用户自定义代币（User Defined Tokens，UDT），例如稳定币及其他在 CKB 上表示的资产。

Fiber 发票可以指定所请求的 UDT，之后支付便可通过支持该资产的通道路由。

这使 Fiber 成为多资产支付网络：网络不同部分可以为不同资产提供流动性，而不要求每笔支付都以 CKB 计价。

Fiber [文档](https://www.fiber.world/docs)还描述了对稳定币、与比特币关联的 RGB++ 资产，以及在 CKB 上发行的 UDT 的支持。

#### **可编程通道逻辑**

第二个区别来自 CKB 的[脚本](https://docs.nervos.org/docs/script/intro-to-script)模型。

Fiber 的[通道](https://www.fiber.world/docs/concept/channels/channel-lifecycle)合约使用 CKB 脚本实现。这意味着，管理通道结算及其他条件的逻辑可以利用 CKB 的可编程交易模型，而不必完全受限于一组固定的基础层支付原语。

这为 Fiber 扩展基于支付通道的金融交互类型提供了更大空间，包括条件支付和资产兑换。

#### **支付与资产兑换**

Fiber 能够支持多种资产的流动性，因此网络能做的不只是把一种资产计价的支付从发送方路由到接收方。

它也被设计为支持资产兑换。

假设 Alice 持有 CKB，却希望完成一笔最终以稳定币计价的支付。能够接入这两种资产通道的路由方或流动性提供者，可以在支付流程中协助完成转换。

Alice 不必先去交易所，把 CKB 换成稳定币，再单独发起支付；资产兑换可以成为支付过程本身的一部分。

关键性质是原子性（atomicity）：兑换的两边通过密码学关联，要么预期兑换完成，要么条件转移失败，资金仍归原所有者。

因此，Fiber 希望将传统上分开的两项功能结合起来：转移价值，以及转换承载价值的资产形式。

#### **与闪电网络互操作**

Fiber 还被设计为与闪电网络互操作，而不是作为孤立的支付系统运行。

[跨链枢纽（Cross-Chain Hub）](https://www.fiber.world/docs/res/cross-chain-htlc#what-is-cch)可以同时运行于 Fiber 和闪电网络，将一个网络上的支付与另一个网络上的对应支付连接起来。Fiber 当前的工具中，包含专门用于两个网络间支付的跨链结构。

假设 Alice 在 Fiber 上拥有资产，却想向通过闪电网络接收 BTC 的 Bob 付款。

枢纽可以接收 Fiber 一侧的入账支付，再向 Bob 发起对应的闪电支付。两次转移通过同一个密码学条件关联：揭示完成一边所需的秘密值，就提供了完成另一边所需的信息。

因此，枢纽提供的是流动性和连接能力，而非托管服务。它不能在拒绝完成出账支付的同时，成功领取入账的条件支付；如果时限届满前条件未满足，转移就会撤回。Fiber 的暂缓结算发票（hold-invoice）设计，利用这种共享原像机制实现原子交换和跨网络支付。

由此形成了一幅更广阔的支付通道网络图景。

闪电网络展示了，如何将比特币变成快速、可路由的支付系统，而不把每笔支付都写到链上。Fiber 从同样的基本机制出发，利用 CKB 的可编程性和资产模型，向多资产支付、支付中的兑换，以及支付网络之间的互操作扩展。



## 开启新的支付模式

当支付变得频繁、小额或对时间敏感时，支付通道的真正优势才显现出来。

传统支付系统通常把经济活动合并为较大的交易：订阅可能每月收费一次，云服务用量可能累积到出账单时才结算，区块链应用也可能等到金额足够大、值得发起链上交易时再支付。

原因很简单：每次支付都有额外开销。

银行卡网络收取固定费用和按比例计算的费用。银行转账涉及中介和结算流程。链上支付消耗区块空间，需要支付网络费。如果支付本身只有不足一美分，这些开销可能超过转移的价值。

支付通道改变了这一成本关系。流动性一旦投入通道，就能反复支付，无需每次都创建新的区块链交易。这使金额更小、频率更高的转移，在经济上变得可行。

### 小额支付

小额支付（micropayments）让用户可以为单份数字价值支付很小的金额，而不必整包购买。

读者可能花不足一美分解锁一篇文章，应用可能为一次数据库查询付费，AI 智能体可能为一次模型推理或一次 API 请求付费。

重点不在某个特定金额门槛，而在于支付金额可以低于传统支付系统或直接链上支付在经济上合理的水平。

数千次交互不必合并成一份订阅或一张账单，每次交互本身都有可能成为一次经济交易。

### 流式支付与实时支付

单笔支付足够便宜时，就可以在极短的时间间隔内反复发生。

想象一辆连接充电站的电动汽车。它不必预先授权一笔大额支付，再按实际用电量对账，而可以在电能交付的同时，连续进行小额支付。

同样的模式也可以用于计算、带宽、存储或其他按量计费的资源。

这些流式支付（streaming payments）未必是资金连续流动、字面意义上的支付“流”。实践中，它们可以是一连串快速、离散的小额交易，紧密跟随资源消耗。

这带来了一种不同的支付模式：价值可以随服务交付而转移，而不必等到很久以后再结算。

### 按使用量付费的服务

如今，大多数数字服务会汇总用量，因为对每个单独操作收费效率太低。

因此，云服务提供商可能按月出账单，API 提供商可能销售额度包，软件产品可能收取固定订阅费，不论客户实际用了多少。

低成本链下支付让更细粒度的计费成为可能。

用户不必每月支付 20 美元获得访问权，而可以只在使用服务时付费：按请求、按兆字节、按计算秒数，或按其他可计量资源的单位收费。

这不意味着订阅会消失，而是服务多了一种选择：让收费更贴近实际消耗。

### 机器对机器支付

当付款方不再是人时，这一点尤其重要。

软件智能体、联网设备和自主机器使用资源的频率，可能远高于人类购物的频率。AI 智能体可能查询多家数据提供者、购买一次模型推理、租用算力执行任务，再向另一个服务付费获取结果，整个过程无需人逐笔批准。

传统支付基础设施主要围绕人类发起相对低频购买的场景设计。[机器对机器商业活动](https://www.nervos.org/knowledge-base/what_are_machine_to_machine_payments)（Machine-to-machine commerce）可能有不同需求：支付需要可编程、自动化、面向全球，即使金额极小也划算。

支付通道很适合这种环境，因为机器可以复用已有流动性，进行大量低延迟支付，无需将每次交互都提交到区块链。

### 游戏、数字内容与打赏

在某些数字体验中，停下来处理一次传统支付所需的成本，相对于交换的价值而言太高。同样的经济逻辑也适用于这些场景。

玩家可以购买小型数字物品或转移价值，无需等待区块链确认。读者或观众可以为单个内容支付很小的金额。用户可以给创作者打赏，即使金额小到不足以承担传统支付处理费用。

共同要求是，支付应该融入交互，而不是打断交互。

### 跨境支付

支付通道网络还可以跨境转移价值，无需让每笔转账都经过传统代理行链条。

发送方可以通过互联网原生网络路由支付，数秒内到达接收方。路由费用由网络决定，而非由一连串银行中介决定。

多资产网络有可能进一步扩展这一模式。如果流动性提供者能够在支付路径中兑换资产，发送方和接收方就未必需要使用同一种资产。

发送方可以用一种货币或代币支付，接收方收到另一种，转换作为转账的一部分完成。

这并不能消除跨境支付的全部难题。外汇流动性、监管、法币出入金渠道和当地接入条件仍然重要。但它可以显著简化底层的价值转移。

这些场景的共同点，不只是支付通道“快”。

更在于，它让反复发生的经济交互成本足够低，可以逐次直接支付。

一次 API 调用、一秒计算、一千瓦时电力，或一小份数字内容，不再仅仅因为支付处理成本过高，就必须并入一笔更大的交易。

到了这里，链下支付基础设施就不只是现有支付的扩容方式。它开始支持那些在传统支付系统和基础层区块链上难以实现，或在经济上根本不可行的支付模式。



## 常见问题

### 什么是链下支付？

链下支付是不把每笔交易都直接记录在区块链基础层上的支付。区块链仍可用于结算、强制执行约定或解决争议。

### 链上支付与链下支付有什么区别？

链上支付由区块链直接处理并记录，链下支付则将部分或全部活动移到基础层之外。这通常能提高吞吐量、降低成本，并加快支付。

### 链下支付比链上支付更快吗？

通常是。链下支付可以避免等待出块和确认，使支付通道等系统在数秒甚至更短时间内完成支付。

### 链下支付更便宜吗？

通常是，尤其是同一套链下基础设施被多次复用时。例如，支付通道不必为每笔支付都缴纳区块链网络费，但仍可能产生路由费。

### 支付通道与链下交易是一回事吗？

不是。支付通道只是实现链下支付的一种具体机制，其他方式还包括托管转账和 Rollup。

### 支付通道如何工作？

两名参与者在链上锁定资金，再通过链下交换已签名状态，反复更新资金分配。开启、关闭通道或需要强制执行约定时，才使用区块链。

### 什么是支付通道网络？

支付通道网络把各个通道连接起来，让用户可以通过中间方路由支付，无需与每个收款人都建立直接通道。闪电网络和 Fiber Network 就是例子。

### 为什么使用支付通道网络，而不是 Rollup？

Rollup 通常用于扩展共享区块链应用，支付通道则专注于快速、反复转移价值。因此，通道特别适合小额支付和其他高频支付。

### 支付通道有哪些缺点？

主要挑战是流动性：资金必须预先投入，支付路径上还必须在正确方向具备足够流动性。因此，通道和路由流动性可能需要主动管理。

### 支付通道能保护隐私吗？

相比完全在链上进行的支付，支付通道提供更好的隐私，因为单笔支付不会公开记录在区块链上。但它并非完全匿名，参与路由的节点仍能观察到一些支付信息。

### 闪电网络和 Fiber Network 有什么区别？

闪电网络建立在比特币上，主要处理 BTC；Fiber 则建立在 CKB 上，设计用于多资产支付、可编程通道逻辑、资产兑换，以及与闪电网络互操作。
