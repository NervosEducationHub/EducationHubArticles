L402 是 [Lightning Labs](https://lightning.engineering/) 开发的一种创新支付协议。它结合了闪电网络与 HTTP 402 Payment Required（需要付款）[状态码](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes)，形成按请求付费访问在线服务的系统。

在实际使用中，它允许服务器要求客户端先完成闪电支付，再开放 API、数据集或数字资源的访问权限。传统认证方式依赖账户或 API 密钥，而 L402 将付款证明视为解锁访问权限的凭证，为 AI 智能体提供简便、安全的支付机制。



## L402 背后的核心技术

L402 协议利用几项基础技术，建立安全、可扩展且顺畅的基于支付的认证系统。各个组件共同支持客户端（如 AI 智能体）与服务提供方之间的顺畅交互。

**闪电网络微支付**

闪电网络是 L402 的底层支付层，使微额交易成为可行方案。作为比特币的 Layer 2 扩容方案，闪电网络能以极低费用实现近乎即时的支付。速度与成本效率的结合尤其有利于微支付，而 AI 驱动的环境通常需要这类支付。

在 L402 中，这些微支付往往是一次 API 调用或获取一个小型数据集的费用。每次请求可能只需几聪，不到一美分，使 AI 智能体能够高效执行数千笔交易，而不会产生显著开销。

**闪电发票：支付请求**

每笔闪电支付都从一张[闪电发票（Lightning invoice）](https://www.nervos.org/knowledge-base/what_is_a_lightning_invoice)开始。它是一个结构化数据对象，规定付款金额、目标节点，以及用于验证支付的密码学哈希。当服务器要求为某项资源付款时，会生成一张发票，作为 HTTP 402 响应的一部分返回客户端。

发票既是支付请求，也是启动认证的触发条件。付款后，客户端会收到一个称为原像（preimage）的密码学值，它是验证所请求资源访问权限的关键要素。

**Macaroon：可编程授权令牌**

Macaroon 提供灵活、去中心化的授权框架。这类密码学令牌可以嵌入条件，称为限制条款（caveats），用来规定到期时间、允许访问的端点或使用次数上限等约束。

在 L402 中，服务器随闪电发票一起签发 macaroon。支付完成后，macaroon 与支付原像（payment preimage）相结合，有条件地授予所请求资源的访问权限。将限制直接嵌入令牌，使分布式系统无需依赖中央权威，也能执行细粒度权限控制。

**支付原像：结算证明**

闪电支付完成后，付款方收到一个与原始发票中哈希对应的密码学原像。客户端通过出示这个原像，证明支付已经结算。

在 L402 中，客户端重试请求时同时发送 macaroon 和原像。服务器依据发票中的哈希验证原像，并确认 macaroon 的条件。验证成功后，客户端便能访问所请求的服务或数据，由此形成安全、自动化的付费访问流程。



## L402 协议如何运作

L402 的运行过程类似于典型的 HTTP 请求周期，但增加了一个步骤：必须先付款，才能获得访问权限。

客户端（例如 AI 智能体）首次尝试访问付费资源时，比如从研究机构下载特定数据集，会向服务器发送标准 HTTP 请求。从客户端的角度看，该请求可能与其他 API 调用没有区别。但如果资源需要付费，服务器不会立即返回所请求的数据，而是返回 HTTP 402 Payment Required 状态码。

响应包含两项重要信息：一张规定资源访问价格的闪电发票，以及一个表示有条件授权的 macaroon。两者共同构成支付挑战。

客户端收到发票后，使用闪电钱包或节点完成付款。这个过程通过闪电网络，将所需数量的聪发送到服务器的节点。支付结算后，客户端获得与该发票关联的支付原像。

付款完成后，客户端重试原始 HTTP 请求。这次，请求的授权头中同时包含 macaroon 和原像。这些值充当已付款的证明。

随后，服务器进行密码学验证，检查原像是否与发票中嵌入的哈希匹配，并确认 macaroon 的条件得到满足。如果各项内容均有效，服务器便处理请求，返回所请求的数据或服务响应。



## L402 与 x402：面向 AI 服务的支付协议对比

L402 和 x402 都旨在满足对自动化支付机制日益增长的需求，让 AI 智能体能够自主接入支付系统。

L402 通过比特币闪电网络，将支付直接集成到 Web 认证中。客户端请求受保护资源时，服务器返回包含闪电发票的 402 Payment Required 响应。发票结清后，客户端出示付款证明以获得访问权限。凭借速度和极低的交易成本，L402 在需要高频微支付的场景中表现出色，例如短时间内连续执行数千次 API 调用的 AI 工作流。

x402 则使用链上交易，而非闪电通道。付款直接发送到区块链地址或智能合约，网关验证结算后才开放访问权限。这种方式优先考虑透明性与可验证的链上结算，适合需要与智能合约或去中心化金融（DeFi）基础设施集成的环境。

L402 强调效率和微额交易的可扩展性，而 x402 提供稳健的链上结算保障。两种模式在机器驱动的经济中发挥互补作用，使 AI 智能体能够自主交易，同时支持不同的运行需求。

## 结语

随着 AI 智能体日益自主、彼此联系更加紧密，实时的机器间支付对顺畅访问服务至关重要。L402 协议将闪电网络与 HTTP 认证机制结合，使即时微支付成为访问 API、获取数据或使用计算资源的前提。

随着采用范围扩大，L402 可能在塑造互联网下一阶段的过程中发挥重要作用：让信息和价值一同顺畅流动，形成由 AI 与 DeFi 基础设施共同驱动、真正可编程的经济。
