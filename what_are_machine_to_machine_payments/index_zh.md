**要点**

- **机器间支付**是指软件、设备或自主系统通过程序为资源付款，无需人类授权每一笔购买。
- **机器经济**是一个商业生态系统，其中软件、API 和联网设备充当买方与卖方，直接相互付款。
- **微支付**是涉及极小金额的资金交换，通常发生在网上。
- **机器支付基础设施**结合了机器身份、可编程支出规则、机器可读的定价，以及足以支持持续进行不足一美分转账的低成本结算。多种设计正在竞争这一角色，包括 Fiber Network 等链下支付通道网络。

打印机发现墨水快用完了，便订购替换墨盒。AI 旅行助手在完成行程安排前，需要查询一次航班数据。电动汽车连接充电桩，读取当前电价，并在用电的同时持续付款。

这些操作都不一定需要人停下手头的事，打开结账页面、输入卡号，再批准交易。

机器可以自行完成。

软件自动作出决策已有数十年历史。正在改变的是，它能够依据这些决策开展经济活动。

随着 AI 近期的发展，智能体或机器可能知道自己需要什么资源、去哪里获取，以及价格是否符合程序设定的预算。但传统商业流程仍假定，在某个环节会有人创建账户、同意计费条款、输入支付凭证或批准购买。

当购买偶尔发生且可以预测时，这种方式可行；但当软件需要以机器的速度自主购买资源、每天可能购买数千次时，它就变得不切实际。

机器间支付正是为解决这个问题而设计的。

人类无需授权每一次购买，而是提前设定规则：机器可以买什么、可以花多少钱，以及必须满足什么条件。之后，机器就能自动发现资源、读取价格、判断购买是否获准、付款，并继续执行任务。

当规模足够大时，产生的就不只是自动支付，而是机器经济：软件、AI 智能体、服务器、车辆、传感器和其他联网系统可以直接买卖资源。

挑战在于，如何构建与机器自身的速度和粒度相匹配的支付基础设施。

## 什么是机器间支付？

机器间（machine-to-machine，M2M）通信的概念早于当前这轮 AI 热潮。最初，它描述的是设备通过有线或无线通信渠道交换信息。

但在数字经济和 AI 的背景下，这一概念已经发生显著变化。“机器”可以是服务器、软件服务、API 客户端、物联网（IoT）传感器、工业控制器、车辆、机器人或 AI 智能体。随着这些系统越来越先进，它们不再只是交换数据，还会消耗数字和物理资源。如今，它们的共同需求是自主获取这些资源，无需等待人类批准。

**机器间支付**是软件、设备或自主系统通过程序为商品、服务、数据、计算能力或其他资源付款的交易，无需人类介入。人类仍承担责任，设定总体预算和政策，但在购买发生时不参与交易环节。

## 机器间支付如何运作？

机器间支付可以采用不同协议和结算网络，但基本流程通常相似：

1. **请求资源：** AI 智能体、应用程序或联网设备请求所需资源，例如 API 响应、数据流、计算任务或一次充电服务。
2. **接收支付条款：** 提供方返回机器可读的指令，说明价格、接受的支付方式以及付款去向。
3. **授权购买：** 客户端依据程序设定的支出规则检查这些条款，例如预算、允许使用的服务或最高价格。
4. **付款：** 如果购买获准，客户端便授权支付或对支付签名，并发送所需的支付信息或证明。
5. **验证并交付：** 提供方验证付款已完成或已获授权，然后交付所请求的资源。
6. **结算：** 底层支付网络按照自身规则转移或结算价值。

购买发生时，无需结账页面或人工批准。支出规则一旦设定，软件就能完全通过代码完成资源请求、授权、付款和使用。

## 什么是机器经济？

机器经济是以机器为买方和卖方的商业生态系统。机器生产资源、使用彼此提供的资源，并为所消耗的资源付款。机器间支付就是让这一系统得以运作的机制。

在这个生态中，机器能够独立执行支付，因此是经济活动的参与者，而不只是工具。例如，一台机器可以生产某种资源（如太阳能发电），另一台机器则消耗这种资源（如充电）。它们还可以直接为这些交换相互付款。由此形成相互连接的网络，硬件设备、软件和自主 AI 智能体以人类无法管理的规模和速度展开交互。

以下示例展示自主支付如何在不同场景下运作，从简单的 token 触发机制到复杂的自主多方账本：

- **基于触发条件的微支付（智能电动汽车充电）：** 电动汽车接入充电站，与充电桩通信，通过 API 确认账户余额，并在充电过程中按千瓦时付款。
- **有条件的智能合约支付（计算）：** AI 智能体为某项任务租用 GPU 算力，并提前锁定付款。计算服务提供方完成任务并返回约定的证明或签名完工记录后，款项便会释放；如果任务未完成，超时后可以退回资金。
- **完全自主的多设备生态系统（AI 智能体供应链）：** 自主软件智能体管理一家工厂。一个 AI 从另一家工厂的 AI 购买原材料，根据实时库存协商价格，并用加密资产即时结算资金。

### 机器经济需要什么基础设施？

要让自主商业活动规模化运行，软件和设备需要的不只是一种转移资金的方式，还需要面向机器设计的商业技术栈，能够处理身份、授权、定价、支付和结算，而无需每一步都有人参与。

**身份与认证：** 软件、AI 智能体和联网设备需要可靠的方法，证明自己是谁或是什么、认证请求，并确定授权其行动的是哪个人或组织。

**可编程支出规则：** 不应让 AI 智能体无限制地访问加密钱包或银行账户。它的权限需要受到规则约束，明确可以花多少钱、可以买什么、可以向哪些交易对手付款，以及这些权限何时到期。

**机器可读的定价：** 价格和支付条款需要用软件能够自动解读的结构化数据表示，而不是埋在价格页面中，或通过结账界面呈现。

**可通过程序使用的支付协议：** 购买获准后，客户端需要一种标准化方式，完全通过代码授权付款、提交证明并接收所请求的资源。

**低成本结算：** 如果服务按 API 调用、推理、兆字节、计算秒数或其他小单位定价，固定交易手续费就不能超过交换的价值。

**低延迟：** 支付授权和验证必须足够快，避免支付步骤成为底层服务的瓶颈。

**互操作性：** 需要通用标准，让 AI 智能体、API、钱包、支付网络和服务提供方能够通信，而无需针对每个交易对手定制集成。

这些组件结合起来，使软件能够在自身运行的程序环境中完成整个商业流程：识别、评估、授权、付款和使用。

### 为什么传统支付系统难以承载机器经济？

传统支付系统能够自动执行交易，但其设计并非为了让软件进行海量、微额且相互独立的购买。

以银行卡支付为例。Stripe 目前在美国的标准定价是，每笔成功的境内银行卡交易收取 2.9% + 0.30 美元。对于一笔 50 美元的购买，固定的 30 美分占比相对较小；但对于一次 0.002 美元的 API 调用，它比支付金额本身高出几个数量级。

这造成了根本性的错配。

传统支付基础设施通常更适合把许多小单位的消费汇总为较大金额的收费，例如每月云服务账单、年度软件订阅或预付余额。

自主软件可能产生相反的需求。AI 智能体或许只想从从未使用过的提供方购买一次 API 响应、几秒计算能力或一次推理，然后在几秒后转向另一项服务。

要让这种模式高效运行，支付层就必须支持小额、高频、由程序授权的交易，而且不能给每次购买都附加一笔显著的固定成本。

传统支付系统可以通过账户、订阅、已保存的凭证和汇总计费支持机器商业活动。它们在经济上难以支持的是更细粒度的模式：每一个微小消费单位发生时，都独立为其付款。

### 为什么微支付对机器经济很重要

软件消耗资源的方式与人类不同。

人可能购买按月订阅的软件服务。AI 智能体则可能在同一任务中，需要一家提供方的一次 API 调用、另一家的几秒计算能力，以及第三家的一次模型推理。

这意味着消费可以极其细化：按请求、推理、兆字节、计算秒数或千瓦时计量。

理想情况下，支付也应达到同样的粒度。

如果每一个微小消费单位都能以经济可行的方式付费，提供方就不必仅仅为了让支付成本划算，而把使用量捆绑成订阅、预付额度或月度账单。

AI 智能体可以在消耗资源时，恰好为消耗的部分付款。

这就是微支付对机器经济的重要性。只要支付基础设施能将每笔交易的成本控制在交换价值以下，就有可能把每一个数字或物理资源消费单位转变为独立的经济交易。

## 机器支付如何融入 Web 技术栈

机器可能购买的大部分资源，如数据、推理、存储和计算能力，已经通过 Web API 提供。Web 基于 HTTP（超文本传输协议，Hypertext Transfer Protocol）运行。客户端通过这一请求与响应协议向服务器请求资源，接收资源时还会收到描述结果的状态码。

20 世纪 90 年代，Web 的早期设计者构建 HTTP 时，明确为原生数字购买预留了一个状态码：402 Payment Required。如果 API 服务器要求付款，就可以拦截客户端请求，并返回 HTTP 402 状态码。这是一种原生客户端错误响应，表示付款前无法提供内容。

当时，由于原生互联网货币尚不存在，402 状态码被搁置。直到 2025 年 5 月 Coinbase [推出](https://www.coinbase.com/developer-platform/discover/launches/x402) [x402 协议](https://www.nervos.org/knowledge-base/what_is_the_x402_protocol)，它才重新得到使用。

### 什么是 x402 与 l402 协议？

x402 协议是一种开放支付标准，重新利用 HTTP 402 状态码，为机器间商业活动提供无状态机制。服务器不会将用户导向可视化结账页面，而是返回 402 状态码，并附上结构化数据形式的机器可读支付条款，包括价格和目标加密钱包地址。客户端检查并验证条款，生成密码学付款证明，再次发起原始 HTTP 请求，这次在请求头中携带付款证明。服务器验证证明后，即时返回所请求的资源。

x402 协议还[不依赖特定区块链](https://docs.cdp.coinbase.com/x402/how-it-works)。其主要用途包括机器间支付、按使用付费的 API，以及无需创建账户的微支付。

[l402 协议](https://www.nervos.org/knowledge-base/introduction_to_l402)将同一状态码引入[闪电网络](https://docs.lightning.engineering/the-lightning-network/l402)。面对需要付费才能访问的请求，服务器返回 402 状态码，以及携带一种名为 [macaroon](https://docs.lightning.engineering/the-lightning-network/l402/macaroons) 的认证令牌和一张闪电发票（Lightning invoice）的响应头。令牌通过包含发票的支付哈希（payment hash），对该发票作出承诺。客户端付款后获得原像（preimage）作为证明，然后同时出示令牌和原像以访问端点。由于令牌在密码学上的有效性已经意味着完成了支付，提供方无需查询支付数据库，就能验证访问权限。

## 区块链和加密货币在机器间支付中发挥什么作用？

机器间支付本身并不要求使用区块链或加密货币。传统支付系统已经能够支持自动计费、已保存的凭证和 API 驱动的支付。

但当软件需要在全球范围内持续、通过程序进行极小金额的交易时，区块链就尤其有用，特别是在买卖双方没有既有关系，也没有共同支付服务商的情况下。

区块链为自主商业活动提供了几项有用的特性：

**可编程授权：** 软件可以控制密码学密钥并直接签署交易，使支付能够在预设支出规则内完全通过代码授权。

**全天候可用：** 公有区块链持续运行，不受银行营业时间、结算窗口或特定国家支付网络的限制。

**全球覆盖：** AI 智能体可以在几秒内向地球另一端的服务付款，无需共同的银行、银行卡网络或许可型支付平台将双方连接起来。

**可编程资产：** 稳定币允许软件使用数字美元交易，同时保留区块链支付的可编程性和全球可访问性。

但直接使用区块链，也会带来自己的问题。

如果每次 API 调用、推理或微小计算单位都成为一笔独立的链上交易，系统就会再次遇到交易手续费、有限区块空间和确认延迟的问题。对于不足一美分的支付，网络手续费很容易超过服务本身的价格。

因此，区块链只解决了机器支付问题的一部分。

对于高频机器商业活动，挑战在于如何结合区块链的可编程性与开放结算能力，以及能够快速、低成本转移微小金额的支付层，而无需把每笔交易都记录在链上。

## Fiber Network：面向机器商业活动的支付基础设施

这正是链下支付网络可以发挥作用的地方。

支付通道（payment channels）不需要将每笔支付都记在区块链上，而是让两位参与者先在链上锁定资金，然后直接交换已签名的余额更新。支付通道网络将这些通道连接起来，使没有直接连接的参与者也能通过路由（routing）完成支付。

由此形成的支付层，恰好适合机器商业活动可能产生的交易：小额、高频、低延迟，而且每笔支付都无需单独支付区块链手续费。

[**Fiber Network**](https://www.nervos.org/knowledge-base/fiber_network) 是构建在 CKB 上的开放、点对点支付与资产交换网络。它使用 CKB 作为结算和规则执行层，将反复发生的支付放在链下通道中完成。

几项特性使这一架构尤其适合机器间支付：

**微支付的成本结构：** Fiber 路由费用与转发金额成比例，不设固定基础路由费。这对不足一美分的支付很重要，因为费用不会仅因交易金额小，就必然超过支付金额本身。

**低延迟：** 单笔支付由路由所涉及的对等节点处理，无需等待新的 CKB 区块。因此，AI 智能体为 API 调用或推理付款时，不必等待基础层确认后才能继续使用服务。

**多资产支付：** Fiber 支持以 CKB 或受支持的 CKB 资产为通道注资，例如用户自定义代币（User-Defined Tokens，UDTs），其中包括稳定币。在整个网络中，这让不同资产都能充当支付流动性，而不必把所有交易都转换为单一原生货币。

**支付与资产交换：** Fiber 不仅旨在路由支付，还能在具备适当流动性时交换资产。这使付款方持有一种资产、收款方最终收到另一种资产成为可能，兑换可以融入支付流程。

**开放路由：** 机器无需与自己使用的每项服务建立直接支付通道。只要存在流动性充足的可行路径，Fiber 就能通过中间节点，沿现有通道路由支付。

对机器商业活动而言，这种组合很重要。Web 层可以告诉软件要付多少钱，以及如何授权购买；Fiber 则可以提供快速、经济地转移价值的底层支付网络。

### 一个可运行的原型：使用 Fiber 为 AI 服务付款

一个名为[ fiber-pay](https://github.com/RetricSu/fiber-pay) 的小型实验项目，展示了这种技术栈在实际使用中可能是什么样子。

该项目把本地托管的 AI 智能体变成付费服务。运营者设定每次请求的价格，并通过带有 L402 风格付费访问控制的 HTTP 端点提供该智能体。

流程如下：

1. 客户端向 AI 服务发送提示词。
2. 由于未附带付款，服务器返回 HTTP 402 Payment Required，并附上一张 Fiber 发票和支付令牌。
3. 客户端通过 Fiber 支付发票。
4. 客户端附上付款证明，重试原始请求。
5. 服务器验证付款并运行 AI 模型。

从用户的角度看，结果很简单：为一次 AI 请求付费，收到一次 AI 响应。

关键在于底层过程：定价通过程序接口提供，支付在链下完成，证明通过 Web 请求传回，而服务仅在付款验证后交付。

fiber-pay 仍是早期实验，而非生产基础设施，但它完整展示了机器支付的基本循环：请求、定价、付款、验证、交付。

它是一个小例子，说明当 Web 协议与低成本支付网络结合时，面向机器的商业活动可能是什么样子。

## 结语

机器间支付的意义不止于让结账自动化。它让软件、AI 智能体和联网设备能够发现资源、评估价格、授权购买，并为所消耗的资源付款，无需人类逐笔批准交易。

在消费细碎且频繁的场景中，这尤其有价值：一次 API 调用、一次推理、几秒计算能力，或少量能源。

构建这样的经济需要多个层次协同运作。机器可读协议可以传达价格和支付要求，可编程授权可以规定软件允许支出的范围，低成本支付网络则可以转移价值，避免每笔微小交易都承担高得不切实际的费用。

由此形成一种新的数字商业模式：人类设定规则和预算，软件在这些范围内自主交易。

## 常见问题

### 什么是机器间支付？

机器间支付是软件、AI 智能体、联网设备或自主系统通过程序为资源付款的交易，无需人类批准每一笔购买。

### 机器间支付如何运作？

客户端请求资源，接收机器可读的支付条款，依据支出规则检查条款、付款，然后获得服务。整个交互过程可以通过程序完成，无需结账页面。

### M2M 支付与物联网支付是一回事吗？

不是。物联网支付是 M2M 支付的一个子集，涉及联网的物理设备；M2M 还包括软件服务、API、服务器和 AI 智能体。

### M2M 支付与 AI 智能体支付有什么区别？

AI 智能体支付是涉及自主 AI 软件的机器间支付子集。M2M 的范围更广，涵盖简单脚本、服务器、车辆、传感器和 AI 智能体等。

### 为什么 AI 智能体需要微支付？

AI 智能体可以按极小单位消耗资源，例如单次 API 调用、模型推理或计算秒数。微支付使付款能够与这种消费方式匹配，无需将所有消费捆绑成订阅或较大金额的账单。

### 机器间支付需要区块链吗？

不需要。传统支付系统可以支持自动支付，但如果支付需要全球覆盖、可编程、持续可用，并能在没有共同支付服务商的双方之间转移极小金额，区块链就很有用。

### 什么是 x402？

x402 是围绕 HTTP 402 Payment Required 构建的开放支付协议，允许服务器返回机器可读的支付条款，客户端自动付款后，再携带付款证明重试请求。

### 什么是 L402？

L402 是一种支付与认证协议，将 HTTP 402 与闪电支付结合，允许客户端支付发票，并使用由此获得的密码学证明访问受保护资源。

### 为什么支付通道适合机器支付？

支付通道允许大量支付在链下发生，无需为每笔支付创建新的区块链交易。因此，它们尤其适合高频、低价值、对延迟敏感的支付。

### 什么是 Fiber Network？

Fiber Network 是构建在 CKB 上的点对点支付与资产交换网络，利用支付通道实现低延迟、多资产支付，旨在支持微支付和机器间商业活动等用途。
