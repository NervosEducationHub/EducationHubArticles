### 要点

- **微支付（micropayment）** 是金额极小的金融交易，通常不足一美元，常常只有几美分甚至不足一美分，以至于传统支付网络无法有利可图地处理它。
- **纳米支付（nano payments）** 和**不足一美分的支付（sub-cent payments）** 将这一概念推向更小的金额，达到百万分之一美元的量级，主要用于机器间商业（machine-to-machine commerce）和 AI 智能体商业活动。
- 数十年来，两大因素阻碍了微支付的广泛采用：人类的心智交易成本，以及传统信用卡网络的固定基础费用。
- 托管式批量处理、运营商直接计费或订阅打包等传统变通方案，能够绕过这些问题，却需要可信中介。
- **Fiber Network** 等 Layer 2 支付通道网络通过在链下路由价值，解决这些瓶颈，实现即时、免 gas 的结算和按次 API 调用计费。

在互联网上传递信息极其便宜。

应用可以发起数千次 API 请求、从世界各地的服务器下载小块数据，或持续传输信息，而无需有人考虑每个数据包的成本。

但历史上，转移资金的情况截然不同。

向人收取 20 美元很容易；收取 0.20 美元可能不太方便；收取 0.002 美元，处理费用可能比付款金额本身还高。

从商业互联网诞生初期起，这种不匹配就一直限制着微支付。

最初的设想很有吸引力：为一篇文章、一首歌、一件游戏道具或其他小份数字内容收取几美分，而不必把一切打包进订阅或更大额的购买中。

但两个问题反复成为阻碍。

第一个是经济问题。传统支付系统的处理成本，并不会随着交易金额按比例下降。金额小到一定程度，收款所需的手续费就会超过付款本身。

第二个是行为问题。即使微小金额支付的处理成本很低，要求人们一天中反复停下来，批准几十乃至几百次小额购买，也会造成阻力。订阅、预付余额和广告通常更省事。

互联网围绕这些限制形成了相应模式。出版商将内容打包为订阅，软件公司出售月度套餐，而非按每个消耗单位收费。平台则使用预付余额或内部记账，避免逐笔处理微小金额支付。

如今，人们正在重新审视这两项限制。新的支付基础设施能够降低转移微小金额的边际成本；与此同时，AI 智能体和其他自主软件，可以在预先设定的预算和权限内购买资源，无需人类逐笔批准。

这改变了微支付的用途。

最值得关注的场景，不再只是让一个人为一篇文章付几美分，而是让软件为其实际消耗精确付费：一次 API 调用、一次模型推理、几秒算力，或一小块数据。

本文解释微支付与纳米支付是什么、为何曾难以普及，以及新的支付架构为何让它们重新受到重视。

## 什么是微支付与纳米支付？

**微支付**是一种金额很小的金融交易，相对于转移的价值，常规支付处理成本或操作阻力已经不可忽略。

它没有公认的美元金额门槛。

某个场景中，一美元也可以算微支付；机器商业则越来越多地涉及不足一美分的金额。关键并非确切数字，而是经济问题：**处理这笔支付的成本，能否低到值得收取这笔钱？**

过去，微支付方案主要针对人类购买行为，例如单篇新闻、歌曲、打赏、游戏道具或小份数字内容。

如今，这个概念正走向更细的粒度。

一个 AI 智能体可能为以下资源付费：

- 一次 API 请求；
- 一次模型推理；
- 几秒计算时间；
- 少量存储空间；
- 对一个数据集的访问；
- 或其他范围明确的数字服务单位。

这也使纳米支付一词流行起来。

纳米支付并不是一个有统一金额门槛的标准化金融类别。它通常指极小金额的微支付，往往不足一美分，而且更可能由程序发起，而非由人手动操作。

例如，Circle 目前将这一术语用于其 Gateway 支付系统。该系统通过链下签署付款、批量结算，支持低至 [0.000001 美元](https://developers.circle.com/gateway/nanopayments)的 USDC 转账。

闪电网络在协议层面体现了同样的思路。闪电支付金额可以用毫聪（millisatoshis）表示，即一聪的千分之一，但可路由的最小金额取决于各条通道的策略。

因此，最好将两者的区别理解为粒度不同，而非存在严格界限。

## 微支付的心智成本

低成本支付网络本身，并不是问题的全部。

1999 年，计算机科学家、密码学家 Nick Szabo 将“[心智交易成本（mental transaction costs）](https://nakamotoinstitute.org/library/micropayments-and-mental-transaction-costs/)”指出为主要心理障碍。他认为，不断评估和批准微小购买所需的认知投入，会让用户疲惫，使固定费率订阅或广告支持模式更有吸引力。Szabo 认为，支付网络变得更便宜，并不会降低这种心智成本，因为没有人愿意一天有意识地权衡 500 次：一道一美分的付费墙究竟值不值得跨过。

但这一限制只适用于人类买家。如今，AI 智能体和[机器间商业](https://www.nervos.org/knowledge-base/what_are_machine_to_machine_payments)的兴起，正在改变局面。当智能体从人预先设定的预算中支出时，就不会反复累积犹豫时刻，人类也不必作出每一个微小决定。因此，微支付如今重新受到关注，更多是作为机器基础设施，而非面向消费者的功能。

## 为什么不能用信用卡支付很小的金额？

另一项限制来自架构：传统银行卡网络从来不是为转移两美分而设计的。刷卡时，交易依次经过支付网关、支付处理商、收单银行、卡组织和发卡银行，每一方都因提供有价值的服务而收取费用，并通过最低基础费用保障自身利润。

美国信用卡交易的[标准](https://stripe.com/pricing)费用，大约为每笔 0.30 美元，另加交易金额的 2.9%。如果顾客想用 0.10 美元购买一篇数字文章，仅固定的 0.30 美元费用就是售价的三倍，商家每卖一份都会亏损。这也是许多商家将刷卡最低消费额定为 5 美元或 10 美元的原因。

为了绕过这一限制，传统平台采用托管式批量处理：用户先在可信中介处充值，中介再以小额逐次扣减余额，并以较大金额、较低频率与银行卡网络结算。[Skype](https://support.microsoft.com/en-us/skype/skype-is-retiring-in-may-2025-what-you-need-to-know) 曾通过 Skype Credit 为通话按分钟计费，[Blendle](https://en.wikipedia.org/wiki/Blendle) 则提供按篇付费新闻服务，两者都曾依赖这一模式。它可以奏效，却占用了用户资金，而且仍需信任一家公司替自己保管钱。

## 微支付如何运作？

上述两项限制都假定付款者是使用银行卡的人。有两点改变了这个前提：首先，软件和机器不会像人一样，因为细小决定而感到疲惫；其次，[支付通道网络](https://www.nervos.org/knowledge-base/ultimate_guide_to_payment_channels)等新型支付基础设施，专门用于避免逐笔手续费的最低门槛，正是这个门槛让银行卡网络无法胜任微支付。

### 传统变通方案与中心化批量处理

广告支持的访问模式，例如 Google 和 YouTube，以及订阅打包，例如 Spotify 和《纽约时报》，仍是大多数出版商的默认选择，恰恰因为它们避免了逐笔定价。[Apple News+](https://www.apple.com/newsroom/2019/03/apple-launches-apple-news-plus-an-immersive-magazine-and-news-reading-experience/) 将 300 多种杂志和报纸打包成每月固定 12.99 美元的订阅，按照读者阅读时长，而非逐笔交易，与出版商分成。

由 Boku 或 Fortumo 等支付处理商管理的运营商直接计费（direct carrier billing），会将购买费用计入用户手机账单。这种方式在亚洲广泛用于数字商品，利用了 NTT DOCOMO 等电信服务商与用户之间已有的信任。

应用商店等平台则通过设置最低定价，解决同类问题的另一种形式，例如应用内购买的 [0.29 美元最低价位](https://www.bloomberg.com/news/articles/2022-12-06/apple-overhauls-app-store-pricing-to-range-from-0-29-to-10-000)。

### 去中心化扩容与 Layer 2 方案

加密货币允许价值在双方之间直接转移，无需依赖可信中介的内部账本。但比特币和以太坊等早期区块链，仍遇到了同样的微支付问题：对极小金额交易而言，链上费用可能太高或难以预测。

总体解决方向是 Layer 2 扩容，即将交易活动移出基础区块链，让每笔支付都不必消耗 Layer 1 区块空间。这里尤其相关的有两类方案：

- **Rollup（乐观或零知识 Rollup）：** Rollup 在基础区块链之外执行交易，将活动合并后，再把数据、状态承诺，以及 ZK Rollup 所需的有效性证明提交回 Layer 1。这能大幅降低单笔交易成本，但每笔用户交易仍会给共享 Rollup 环境带来一定边际成本。因此，Rollup 特别适合扩展通用应用和共享状态的处理能力，而不限于支付。
- **支付通道：** [支付通道（payment channels）](https://www.nervos.org/knowledge-base/what_are_payment_channels)采用更专门的方式：两名参与者先在链上锁定一次资金，随后通过交换签名状态，反复在链下更新余额，无需将每笔支付发布到区块链。支付通道网络将许多这样的通道连接起来。当发送方与接收方没有直连通道时，只要沿途有足够流动性，支付就能通过中间节点路由。闪电网络在比特币上采用这一架构，Fiber Network 则在 CKB 上采用它。路由节点仍可收费，参与者也必须管理通道流动性，但每笔支付无需单独支付基础层交易费，因此支付通道尤其适合频繁、低金额的转账。

两种方案都并非万能。Rollup 更适合通用区块链应用扩容，支付通道则专为快速、反复的价值转移而优化。

因此，支付通道尤其适合微支付。通道注资后，单笔支付无需承担基础层费用或等待确认，即使频率很高，极小金额转账也能保持经济可行性。

这也让**免 gas 支付（gas-free payments）** 有了用武之地。这个术语通常指：活动在链下处理或批量结算，用户因此不必为每次转账单独支付区块链网络费。例如，Circle Gateway Nanopayments 让买家一次存入 USDC，再为低至 0.000001 美元的转账签署链下付款授权，随后由 Circle 汇总到链上结算。

支付通道网络也采用类似的高频交易、低频结算模式，却不要求所有参与者都把资金放在同一家公司的内部账本中。因此，它适合那些要求支付开放、频繁且金额极小的应用：

**按次 API 调用付费：** 应用或 AI 智能体可以为单次 API 请求付款，无需依赖订阅、预付额度或月度账单。

**流媒体与内容：** 通过流支付（streaming payments），用户可以连续支付小额款项，使付款与实际消费的视频、音频或其他内容量相对应。

**机器间（M2M）商业：** 软件、AI 智能体和联网设备可以在消耗带宽、算力、数据或能源等资源时直接付款。机器间支付使这一切无需人类逐笔授权即可完成。

## 为机器经济提供支持：Fiber Network

**支付通道**是一种机制：双方先在共享链上合约中锁定资金，随后在链下签署更新后的余额，完成多次支付，只在开启或关闭通道时回到区块链。**支付通道网络**是一组相互连接的支付通道，允许一笔支付经过多个中间节点路由，因此双方无需直接为彼此建立并单独注资一条通道。

[Fiber Network](https://www.fiber.world/) 是建立在 CKB 区块链上的开放[点对点支付通道网络](https://www.nervos.org/knowledge-base/fiber_network)。正如闪电网络将比特币支付通道连接起来，Fiber 也把 CKB 上的通道连接成可路由的网络。

### 实现即时、低成本路由

通道在 CKB 基础层完成注资后，Fiber Network 内的交易实际上就绕过了区块链出块时间。由于这些更新完全在链下完成，也不需要全局共识，因此能够以一次普通网络 ping 的速度即时结算。

此外，这些链下更新不占用基础层网络资源，因此发送一笔不足一美分的支付，其边际成本接近零。这让开发者可以构建大规模、高频支付流，而无需将资金不断消耗在支付给网络验证者的费用上。

### 为可编程资产而构建

由于 CKB 的[脚本](https://docs.nervos.org/docs/script/intro-to-script)环境高度可编程，Fiber 的通道规则不像闪电网络那样固定。开发者可以定义通道如何授权、更新、结算和处理争议，使 Fiber 能在同一通道中原生支持多种资产，例如 CKB、稳定币、在比特币上发行的代币，以及其他用户自定义代币，而不必让所有支付都经过同一种基础货币。

正是这种可编程性，使 Fiber 被定位为专门服务机器经济的基础设施，而不只是让人与人之间更快转移加密货币的方式。机器经济是一种新兴环境：AI 智能体、联网设备、自主服务等软件直接向其他软件买卖资源，无需人类逐笔批准。

*关于 Fiber 架构的更深入介绍，参见*[ *《Fiber：下一代支付网络完整指南》*](https://www.nervos.org/knowledge-base/what_is_fiber) *以及*[ *《AI 智能体如何付款？机器间支付指南》*](https://www.nervos.org/knowledge-base/how_do_ai_agents_pay_for_things)*。*

## 结语

数十年来，不足一美分的转账始终受到技术与心理因素的限制，如今数字基础设施终于追上了这一愿景。将认知负担交给 AI 智能体，将交易负担交给免 gas 的支付通道，数字经济便不再受制于传统信用卡网络的固定基础费用。随着 Fiber Network 等去中心化基础设施提供即时、可编程的结算，价值像数据一样持续、无缝流动的未来，已经有了基础。

## 常见问题

### 微支付如何运作？

微支付通过尽量降低或消除逐笔交易成本来运作，正是这种成本让小额支付在传统网络上无利可图。它可以采用预付余额、中心化记账、合并计费，或支付通道等区块链 Layer 2 方案。

### 微支付能盈利吗？

可以，但前提是每笔交易的处理成本远低于付款金额。0.30 美元另加 2.9% 的银行卡手续费，会让两美分的支付严重亏损；闪电网络、Fiber Network 等支付通道网络，或 Circle Gateway 纳米支付这类免 gas、批量处理的支付网络，可以将单笔支付的边际成本压低至不足一美分，使按篇文章、按次 API 调用和按 token 付费等商业模式变得可行。

### 微支付与纳米支付有什么区别？

微支付通常指金额不足约一美元、往往只有几美分的交易，由人为单次数字购买支付。纳米支付则指机器或软件执行的自动、连续、低于一美分的交易，金额往往只是几分之一美分。

### 纳米支付的金额可以低到多少？

在目前的加密原生系统中，纳米支付可以低至 0.000001 美元，即 USDC 等稳定币的最小基础单位。这通过批量、免 gas 的结算实现，将一次链上交易的成本分摊到数千笔单独支付中。

### 纳米支付有哪些用途？

纳米支付专门用于超高频自动化任务。常见场景包括数据流传输的实时连续计量、按次 API 调用付费，以及 M2M 商业中自主硬件设备之间细粒度的资源协商。

### 免 gas 纳米支付如何运作？

免 gas 纳米支付将极小金额的链下付款授权汇总起来，随后以大型合并批次在链上结算，从而实际上消除逐笔支付的区块链网络 gas 费。
