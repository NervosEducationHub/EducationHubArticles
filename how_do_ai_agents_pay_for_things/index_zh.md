## 什么是 AI 智能体支付？

开始探索这个领域时，你会遇到几个紧密相关、经常混用，但含义略有差别的术语。深入讨论之前，有必要先把它们清楚地区分开。

**AI 智能体支付（AI Agent Payments）** 是由软件智能体自主执行、在购买发生时无须人类介入的金融交易。人类设定边界，例如预算、支出速率和到期时间，智能体则在边界内自由交易。智能体为一次 API 调用付款，就是一个例子。

**机器间经济（Machine-to-Machine Economy，M2M）** 或 **自主商业（Autonomous Commerce）**，指这类交易大规模发生的商业生态。在这个系统中，软件智能体、智能设备和推理端点自主发现服务、协商条款、相互购买资源，交易过程中没有人类参与。自主商业是这一经济形态充分实现后的状态，人类只设定总体策略，而不逐笔批准购买。



## 为什么信用卡无法满足自主商业的需求

银行卡网络所服务的商业形态截然不同：客户与商家之间相对独立、由用户主动发起的购买。自主软件改变了这种形态。一个智能体完成单项任务时，可能需要进行数十次甚至数百次微小的经济交换，金额往往不足一美分。

这暴露了传统银行卡模式的几个弱点：

* **金额极小时，经济上不划算。** 银行卡处理通常在比例费之外，还收取固定的逐笔费用。例如，Stripe 目前对美国境内标准线上银行卡交易[收费](https://stripe.com/pricing)为 2.9% \+ 0.30 美元。按这一价格，为单次 API 请求收取 0.002 美元显然不可行，因为仅固定处理费就达到付款金额的 150 倍。  
* **支付流程比它所支付的交互本身还重。** 银行卡授权实时完成，但清算与结算发生在之后；信用卡结算通常需要一至三个工作日。智能体不必等待结算，商家可以根据授权结果提供服务；但每购买一点计算、数据或推理资源，都完整走一遍银行卡授权、清算、对账和结算流程，并不适合机器规模的微支付。  
* **委托能力必须额外叠加。** 传统银行卡凭据标识的是账户或持卡人，而自主智能体需要更细粒度的能力：证明某个智能体获准支出、限制它可以买什么以及花多少，并让权限可以到期或撤销。支付行业已经在建设这一层能力：Stripe 的 Shared Payment Tokens 可以按商家、金额和时间限定范围，Mastercard 的 Agent Pay for Machines 则引入智能体凭据认证和由程序强制执行的支出控制。  
* **服务消费完毕很久之后，支付仍可撤销。** 持卡人通常可在付款后 120 天内提出争议，有时甚至更久。对于购买实体商品或遭受欺诈的人，这种保护有其意义。但软件购买的往往是短暂资源，例如一次推理、一次数据库查询或几秒计算，它们会立即交付并被消耗，这种保护机制在此就不太合适。

实际中的变通办法，是干脆不为每次交互单独付款，而是把大量微小用量汇总到预付余额、订阅、平台账户或周期账单之中。

这样行得通，却削弱了自主商业的许多潜力。智能体并没有在消费资源时自由付款，而是由开发者代它建立账户、预存余额、管理账单关系并核对用量。

要让机器成为独立的经济参与者，支付就必须像它们消费的服务一样，足够细粒度且可编程。



## AI 支付基础设施的层次

传统银行卡网络无法满足软件的需求，因此需要一套新的金融技术体系。AI 智能体支付基础设施通常分为四个不同层次：

### 身份层

**这个智能体是谁？它代表谁？**

每笔交易都需要一个主体。传统银行和信用卡处理机构依赖与人类身份绑定的 KYC（Know Your Customer，了解你的客户），例如社会安全号码、护照、实体地址，以及多因素认证。它们假设授权交易时，键盘前坐着一个人。

当软件依据委托权限发起支付时，必须同时验证两件事：智能体的身份，以及背后用户的意图。因此，智能体必须具有可验证身份，既与其所代表的人或组织区分，又能证明二者的关联。智能体身份通过密码学密钥对、去中心化标识符（Decentralized Identifiers，DIDs）或可验证凭证（Verifiable Credentials，VCs）处理。AI 智能体持有自己的安全身份，可以用数学方法验证，因此能够在没有人类中介的情况下完成身份认证。由此，行业越来越重视在 KYC 之外，同时实现了解你的智能体（Know Your Agent，KYA）。

### 授权与治理层

**它可以花多少、买什么、到什么时候，以及由谁负责？**

授权书（mandates）位于这一层。授权书是一种经过密码学签名、机器可读的数字授权，编码了自主交易的具体参数，规定购买范围、资金限额、智能体身份以及权限到期时间的边界。

治理也属于这一层，因为问责要么在授权时得到落实，要么根本无从落实。正因为上层的推理过程不是确定性的，这一层必须保持确定性：受规则约束、可审计且清晰可理解。智能体可以灵活判断自己需要一个付费数据集，而授权层则按固定规则判断是否允许这笔支出。

### 执行与协议层

**如何请求支付、协商并确认？**

执行层处理交易的实时路由、签名和程序化结算。

传统方法依赖 Stripe、PayPal 等支付处理机构零散且专有的 API，开发集成工作量很大。这些系统假设有人类在场，因此经常触发反欺诈检查、MFA（Multi-Factor Authentication，多因素认证）和人工审批，任何一项都会立即打断自主的机器间操作。

基于区块链的支付基础设施使用开放、程序化的标准，让 AI 智能体能够借助智能合约，同时完成协商、验证服务交付和授权支付。

为衔接智能体意图与支付的实际执行，主要科技和金融公司已推出密码学信任框架和商业框架，标准化这些机器之间的交互：



| 协议 | 创建方            | 核心机制                                               | 主要货币                                          |
| -------- | --------------------- | ------------------------------------------------------------ | --------------------------------------------------------- |
| **x402** | Coinbase & Cloudflare | 重新利用 HTTP 402 Payment Required。智能体遇到付费墙后，签署链上交易并重试。 | 稳定币                                               |
| **MPP**  | Stripe & Tempo        | 使用 HTTP 402，但创建链下会话。智能体预先授权支出限额，再在该限额内进行流式支付。 | 法币、稳定币、加密货币                                |
| **AP2**  | Google                | 使用可验证凭证（VCs）和密码学授权书，证明智能体已获得用户的支出许可。 | 不限币种（传统银行卡与银行、稳定币和加密货币） |



**注**：虽然这里把这些协议归入执行层，它们并不限于路由和结算。X402 包含授权步骤：智能体签署支付授权，协调服务（facilitator）先验证授权，再在链上结算。AP2 则使用可验证凭证和密码学授权书，证明智能体已获得用户的支出许可。

### 结算与网络层

**价值实际在哪里转移？多久可以再次使用？**

即使智能体已经表明身份、获得支出许可，并就支付执行方式达成一致，仍然需要某种机制实际转移价值。

这就是结算层。

结算不应与授权或最终性（finality）混淆。授权告诉商家，支付已获批准；结算是支付参与方之间实际转移资金；最终性描述的是，按照结算系统规则，该转移何时变得不可撤销。

传统法币支付基础设施难以匹配自主软件的需求。

这并不意味着每种传统支付都很慢。银行卡网络几乎可以立即授权购买，自动清算所（Automated Clearing House，ACH）支持当日结算，FedNow 等较新系统可以实时结算。两者的不匹配远不只是延迟问题。

当今支付基础设施大多围绕已知参与方之间的独立交易设计，依靠银行、银行卡网络、支付处理机构、商户账户和既有账单关系运作。自主商业带来了截然不同的模式。软件可能需要全天候、跨境地从许多独立服务发现和购买资源，金额又小到难以为每次交互单独建立常规支付交易或计费关系。

**区块链与加密资产更适合这样的环境。**

加密技术让货币成为软件可以原生持有、验证和转移的对象。智能体能够通过密码学密钥控制钱包，以程序方式发起交易，与另一台机器交易之前，无须先与其建立银行卡账户或传统银行关系。公共区块链网络跨境持续运行，稳定币则提供价格稳定、能够在这些网络间流转的交换媒介。

换句话说，加密资产移除了许多以人为中心的支付系统所依赖的前提。货币变得原生于互联网：可编程、全球可访问、机器可读，并通过密码学而非机构授权来转移。

因此，基于区块链的资产是自主商业的天然基础。

但还有另一项约束。

如果每笔机器支付都单独在链上结算，那么每次 API 请求、推理、数据库查询，或每一秒计算，都会成为一笔独立的区块链交易。每笔交易都占用区块空间、产生手续费，并受底层链的确认与最终性特征约束。

偶尔付款时，这完全可行。但当机器持续交换价值，可能发生数千次乃至数百万次小额交互时，要求每次交互都对应一笔独立链上交易，就不现实了。

支付通道网络进一步把高频支付执行移到链下，同时保留区块链作为底层的强制执行与结算层。



## Fiber Network：面向智能体经济的开放支付网络

[Fiber Network](https://www.nervos.org/knowledge-base/what_is_fiber) 是构建于 [CKB](https://www.nervos.org/knowledge-base/nervos_overview_of_a_layered_blockchain) 区块链上的开放点对点支付网络。

其基础是支付通道（payment channels）：双方将资金锁入通道，通过在链下更新余额进行多次支付，无须把每笔交易发布到区块链。通道开启、关闭或发生争议时，CKB 充当底层的强制执行与结算层。

与围绕单一原生资产设计的支付通道网络不同，Fiber 从设计上就支持多资产。它支持 CKB、[UDT](https://github.com/nervosnetwork/rfcs/blob/master/rfcs/0025-simple-udt/0025-simple-udt.md) 和稳定币，以及 [RGB++](https://www.nervos.org/knowledge-base/ultimate_guide_to_rgb_rgbpp_and_client_side_validation) 资产；其跨网络架构还支持 Fiber 与比特币闪电网络之间的支付和兑换。

这对自主商业尤其有用，因为智能体可能需要用稳定币付款、在资产之间兑换，或与不同支付网络上的服务交互。

对于自主商业，Fiber 有两项特别重要的优势：它让高频微支付在经济上可行，也从 CKB 获得了可编程性更强的基础。

### 实现微支付与流式支付

微支付（micropayment）是金额极小的交易，通常不足一美分，用于一次数据库查询等单个动作。流式支付（streaming payment）把这一理念延伸到时间维度，在服务被消费的同时，持续释放一连串小额支付，例如按秒支付计算费用。

Fiber 将重复支付移到链下，使这两种模式都具有实用性，每次价值转移不必再承担单独一笔区块链交易的成本和延迟。

**没有固定基础费。** Fiber 的路由[费率公式](https://www.fiber.world/docs/concept/routing/trampoline-routing#fee-formula)与转发金额成比例，而不额外收取固定的逐笔费用。每个路由节点都自行设置比例费率，以转移价值的百万分之几计。这使该模型特别适合极小额支付，因为固定交易费用很容易超过转移金额本身。

**低延迟支付执行。** Fiber 支付由路径上的相关对等方处理，每次更新都无须全网共识。因此，支付可以在链下以极低延迟完成，而 CKB 仍作为最终的强制执行与结算层。

### **可编程性与协议集成**

Fiber 构建于高度灵活的基础链 CKB 之上，通道规则通过可编程脚本实现。开发者在定义通道如何授权、更新、结算和处理争议方面，拥有更大自由。

**表达能力。** Fiber 利用 CKB 表达能力丰富的智能合约环境管理通道逻辑。这让脚本直接在应用层运行，能够在通道内实现条件支付、自动支出上限和自定义释放条件等定制执行逻辑。

**协议无关的集成** Fiber 已[计划](https://github.com/nervosnetwork/fiber/issues/1255#10-implementation-roadmap)实现 x402 协调服务，其开放路由系统也可作为其他新兴协议的底层支付基础设施。

### 构建自主经济：现实用例

对于构建去中心化应用的团队，Fiber 的实际吸引力在于，它消除了缓慢、昂贵结算带来的架构约束。无论开发者构建的是面向消费者的应用，还是自主智能体，生态已经展示了必要的基础组件。

如今，社区开发者正利用这些组件开展实验，创建了支持按秒流式支付的 [Fiber Audio Player](https://fiber-audio-player.vercel.app/)、提供 Stripe 风格界面的 [fiber-checkout](https://github.com/salmansarwarr/Fiber-checkout)，以及提供付费访问的 [Fiber L402](https://github.com/RetricSu/fiber-l402) 等工具。社区开发者在 [Nervos Talk 论坛](https://talk.nervos.org/)积极讨论这些想法并发布早期原型，你或许能从中找到有趣或值得借鉴的内容，继续构建自己的项目。



## 结语

从以人为中心的商业转向机器间经济，需要从根本上重新思考金融价值的转移方式。传统法币支付基础设施受制于较高的基础费用、人工身份检查和缓慢结算，无法支持自主软件所需的微小、高频交易。

科技与加密生态中的开发者正在通过新的身份层和执行协议，快速标准化智能体的认证与协商方式，但结算仍是主要瓶颈。Fiber Network 这样的基础设施为新经济提供了关键支撑。它利用构建在高表达能力区块链上的支付通道，消除传统支付基础设施的使用障碍，将交易成本降至接近零，并实现近乎即时的结算速度。随着开发者继续实验和探索，自主商业与流式支付正从概念转变为现实中可用的工具。
